`GameWorld`는 Windows API나 스레드·송신 콜백을 사용하지 않습니다. 게임 로직은 수신 대상과 패킷의 목록을 반환하고 `PacketHandler`가 전송합니다. 게임 상태는 로직 스레드만 수정하고 종료 시 join 후 초기화합니다. 큐 잠금을 잡은 채 게임 요청을 실행하거나 송신하지 않습니다.

CMake의 `server_core`와 `chat_client`가 구현을 각각 한 번 컴파일합니다. `zpd-server`, `zpd-client`, `zpd-server-tests`는 필요한 라이브러리를 연결합니다. 기존 테스트 실행 파일의 대화형 진입은 호환을 위해 유지했습니다.

## 이름 변경

| 이전 | 현재 | 이유 |
|---|---|---|
| Define.hpp | ConnectionKey.hpp / NetworkIo.hpp / NetworkSettings.hpp | 식별자·I/O·설정을 분리 |
| PacketCode.hpp | MessageCode.hpp / ErrorCode.hpp | 통신 방향 코드와 오류 의미를 분리 |
| ClientInfo | ClientConnection | 단순 정보가 아닌 소켓/I/O 수명 관리 객체 |
| ConnectionKey.clientId | ConnectionKey.slotIndex | 플레이어 ID가 아닌 재사용 슬롯 |
| GameSession | RoomSession | 현재 모델의 실제 역할은 방 |
| PlayerState::Connected | PlayerState::AwaitingEntry | 개발용 입장 전 상태임을 명확히 표시 |
| PacketHandlerEvent | ServerEvent | 연결·수신·종료 이벤트의 공통 자료형 |
| Delivery.connection | OutboundPacket.recipient | 목적지와 송신 패킷임을 명시 |
| PacketHandler.Run / Handle | Start / ReceiveBytes | 시작과 원시 수신 바이트 접수 구분 |
| RunEchoClient / InteractiveClient | RunChatClient / RoomChatClient | 방·채팅 클라이언트 역할 반영 |
| Command / Process / Snapshot | HandleInputLine / HandleServerPacket / ApplyRoomSnapshot | 입력·처리 대상과 동작 명시 |

## 검증 실행

저장소 루트에서 실행합니다. 각 모듈의 CMake 설정은 루트 설정에서 연결됩니다.

```powershell
cmake --preset windows-x64
cmake --build --preset debug
ctest --preset debug
python -X utf8 mockclient/tests/chat_client_tests.py out/build/windows-x64/Debug
```

실행 파일 경로는 기존과 같습니다. Unity 공유 범위와 권장 방식은 [common 안내](../common/README.md)를 참고하세요.

## 게임 확장 계층

`Session`은 ConnectionKey와 userId를, `User`는 게임 상태·방 소속·위치를 가집니다. 게임별 코드는 `server/game`에서 `GameLogic`을 구현하고 `GameContext`를 통해 조회·위치 변경·알림을 수행합니다. [개발 가이드](게임_로직_개발_가이드.md)를 참고하세요.
